🏆 Reto del Módulo 1 — Git Básico

🎯 Misión

Demuestra que controlas el flujo de las 3 áreas y que sabes proteger tu proyecto antes de publicarlo.

📝 Parte 1 — Preguntas

1. ¿Qué hace exactamente git add archivo.txt?

2. ¿En qué área haces los cambios normalmente, antes de preparar nada?

3. ¿Cuál de estos archivos nunca debería subirse a GitHub?

4. ¿Cuál es el orden correcto?

🧪 Parte 2 — Evidencia práctica

Crea un repositorio de prueba y pega aquí la salida de tus comandos.

Tarea:

  1. Crea un .gitignore con node_modules/ y .env
  2. Haz 2 commits con mensajes descriptivos
  3. Pega el resultado de git log --oneline


💡 Ver pistas

El orden del flujo es Working → Staging → Repository. git add elige, git commit confirma.

Un buen mensaje dice qué cambiaste y por qué: feat: agregar formulario de contacto.

Si tu .env ya se subió, bórralo de la caché y revoca el secreto. Por eso el .gitignore va antes del primer push.
