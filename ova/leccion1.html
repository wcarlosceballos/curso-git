📗 Lección 1 — Git Básico

📌 Idea central

Git no guarda "archivos": guarda cambios. Cada commit es una foto del proyecto con una nota que explica qué cambió y por qué. Tu valor no está en teclear comandos, está en escribir commits que tu yo del futuro pueda entender.

1. ¿Qué problema resuelve Git?

Git es un sistema de control de versiones. Sin él, guardar el estado de un proyecto significa copiar la carpeta entera a otra llamada proyecto_v2_final. Con Git guardas solo la diferencia entre versiones y puedes volver a cualquier punto anterior.

2. Configuración inicial

Tu nombre y correo viajan dentro de cada commit. Si no los configuras, tu trabajo queda firmado por un desconocido.

git config --global user.name "Carlos Ceballos"
git config --global user.email "tu@correo.com"
git config --global init.defaultBranch main

git config --list --global    # verificar

3. Las 3 áreas — el corazón de Git

Este es el concepto que más cuesta. Si entiendes las 3 áreas, entiendes Git.

 📁 Tu carpeta          📦 Preparado          💾 Historial
┌────────────┐        ┌────────────┐        ┌────────────┐
│  Working   │  add   │  Staging   │ commit │ Repository │
│  Directory │ ─────► │  (Index)   │ ─────► │            │
│            │        │            │        │            │
│ Editas aquí│        │ Decides    │        │ Confirmado │
│ archivos   │        │ qué entra  │        │ No se      │
│ sueltos    │        │            │        │ borra fácil│
└────────────┘        └────────────┘        └────────────┘

La idea clave: Git te obliga a pasar por una decisión explícita. Nada entra al historial sin que tú lo apruebes. Por eso git add no es "guardar" — es elegir qué va en la próxima foto.

El staging area es lo que hace útil a Git: puedes tener 10 archivos modificados y preparar solo 2.

git status                    # ver qué hay en cada área
git add Dock.md app.js        # solo estos dos
git commit -m "Corrige dockeo en móvil"
# los otros 8 siguen sin preparar

4. Comandos del ciclo básico

ComandoQué hace
git initCrea el repo — una sola vez
git statusSiempre antes de commitear
git add archivo.txtPreparar un archivo
git add .Preparar todo lo modificado
git diffVer qué cambiaste sin preparar
git diff --stagedVer qué vas a commitear
git commit -m "msg"Confirmar
git log --onelineHistorial resumido

5. Buenos mensajes de commit

Un commit mal escrito es una bomba de relojería para tu equipo y para tu yo del futuro.

git commit -m "arreglado"                          # ❌ inútil
git commit -m "Corregir validación de email"       # ✅ útil

Regla de oro: el mensaje dice qué cambiaste y por qué, no cómo.

TipoEjemplo
featfeat: agregar recuperación de contraseña
fixfix: evitar doble envío en el formulario
docsdocs: explicar la instalación en el README

6. .gitignore — hazlo ANTES del primer push

Por defecto Gitlify sí sube todo, incluidos tus archivos personales y secretos. Esta es la causa número uno de filtrar contraseñas.

# Dependencias
node_modules/
vendor/

# Secretos — NUNCA subir
.env
.env.local
*.key
id_rsa

# Sistema operativo
.DS_Store
Thumbs.db

# Herramientas
.vscode/
.idea/

Regla: se crea antes del primer push, no después. Si ya subiste algo que debías ignorar, borrarlo del historial requiere filter-repo — por eso es mejor prevenir.

7. Ejemplo completo

mkdir mi-proyecto && cd mi-proyecto
git init

printf 'node_modules/\n.env\n' > .gitignore
echo "# Mi proyecto" > README.md
echo "console.log('hola')" > app.js

git add .
git commit -m "chore: estructura inicial del proyecto"

echo "console.log('hola mundo')" > app.js
git diff                    # revisa antes de preparar
git add app.js
git commit -m "feat: mensaje de saludo en español"

git log --oneline
🧪 Ejercicio 1 — Primeros pasos
  1. Crea ~/practica-git-1 e inicializa el repo
  2. Crea un .gitignore con node_modules/ y .env
  3. Crea README.md con una línea de descripción
  4. git add . y commit → revisa con git log --oneline
  5. Edita el README y mira el cambio con git diff
  6. Prepara solo el README y commitea
  7. Comprueba con git status que el resto quedó intacto

🎯 Criterio de éxito: 2 commits con mensajes descriptivos, y entiendes por qué git diff va antes de git add.
