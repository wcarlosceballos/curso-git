🏆 Reto del Módulo 2 — Ramas y Conflictos

🎯 Misión

Demuestra que sabes integrar ramas y, sobre todo, resolver un conflicto real. Esta es la habilidad que más se necesita en un trabajo.

📝 Parte 1 — Preguntas

1. En un archivo con conflicto, <<<<<<< HEAD indica…

2. Ya borraste las marcas del conflicto. ¿Qué comando es obligatorio para confirmar que quedó resuelto?

3. Quieres deshacer un commit que ya subiste al repositorio compartido. ¿Cuál es la opción segura?

4. ¿En qué situación no ocurre un conflicto?

🧪 Parte 2 — Evidencia práctica

Tarea: provoca y resuelve un conflicto de verdad.

  1. Crea la rama feature/titulo y cambia la primera línea del README.md
  2. Vuelve a main y cambia la misma línea de otra forma
  3. Ejecuta git merge feature/titulo →(conflicto)
  4. Pega abajo el bloque con las marcas <<<<<<< que te mostró
  5. Resuélvelo, borra todas las marcas y commitea


💡 Ver pistas

Las tres marcas son <<<<<<< (tu rama), ======= (separador) y >>>>>>> (la rama que llega).

Si después de editar Git sigue diciendo que hay conflicto, es que quedó una marca sin borrar o faltó el git add.

En repositorio compartido, nunca uses reset --hard sobre main: borra commits para todos.
